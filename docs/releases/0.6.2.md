# Zyra 0.6.2

Status: release candidate. Not yet published or installed.

> Temporary unsigned release exception approved for 0.6.2. Windows and macOS packages will not be code-signed or notarized. The embedded browser retains the documented security patch gap in [RELEASE.md](../../RELEASE.md). This candidate does not upgrade Electron or claim that Chromium is current.

This patch collects the Desktop and TUI stabilization work since 0.6.1, together with browser-extension and mobile-host fixes. CLI/runtime and Desktop versions remain in lockstep at 0.6.2. The Android review app and browser extension retain their own package versions.

## Chats and connection status

- Compatible busy agent services stay connected while a code update waits. A changed code fingerprint alone no longer disconnects the observing client.
- Desktop, browser, TUI and mobile distinguish confirmed, stale and disconnected status. Runtime namespace and per-start identity identify the service being observed; cached chat history does not prove current activity.
- Development and installed Desktop remain separate. Terminals opened inside Desktop inherit its namespace without gaining Desktop control authority. Development Settings cannot overwrite or remove the installed global terminal command.
- History loading, corrected streamed text, work summaries, pending questions, approval presentation and interrupted-turn handling receive regression fixes. Saved chats and permission choices are preserved.

## Browser and files

- Native overlays keep browser pages live beneath menus. Recording setup, ownership and cleanup are more predictable, and browser tabs retain their saved order and workspace state. Private tabs remain excluded from persistence.
- Browser sharing confirms its connection instead of treating cached pairing as live. Automatic reconnection stays with the selected installation rather than silently moving to another service on a reused port.
- Windows file associations use Material file-type icons instead of the application logo. Explorer entries use normal menu placement, and explicit choices belonging to other applications remain untouched.
- Standalone previews use one header with the Zyra menu and native window controls. Dirty edits block reload, close follows the existing save guard, and menu errors remain visible.
- File navigation, local HTML handling, accessory windows and browser-extension rendering receive fixes. Inline visualizations use themed, sandboxed HTML/CSS/SVG views, with source and download controls; TUI shows their text summaries.

## Settings and connected clients

- Settings use direct destinations and consistent controls for providers, models, permissions, appearance, usage, mobile access and terminal setup. Supported local harness usage is indexed for range-based summaries.
- Provider/account work is kept off the main UI thread where supported. Saved provider choices, delegated model preferences and bounded background memory work retain their existing authority checks.
- Mobile-host updates cover history, attachments, pending responses, notifications and connection freshness. Development mobile listeners keep a separate saved port. Android source and review tests are included in the repository; this Desktop/TUI release does not imply that a new Android APK has passed device acceptance.

## Installation and verification limits

Windows may show an Unknown publisher or SmartScreen warning. macOS may require approval in Privacy & Security. Production-protected media playback may remain limited without VMP signing. The unsigned exception applies only to 0.6.2; it does not weaken the default signed release workflow.

Publication still requires review, passing release gates, builds on the native Windows/macOS/Linux runners, complete updater metadata, checksums, and downloaded-draft readback. The owner repository cannot currently start hosted jobs. The approved build-helper path can provide native evidence for the exact candidate SHA; those builds and artifact checks remain pending. Local or mocked tests do not replace native artifact or installed-app verification.

Cross-installation active-work discovery, automatic takeover, runtime rollback and the proposed updater preparation handshake are not part of this patch. A service restart can interrupt active work; installation must preserve user data and close only processes belonging to the affected Zyra instances.
