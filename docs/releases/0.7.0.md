# Zyra 0.7.0

Status: draft release candidate. Not published or approved for installation.

This candidate collects the local work accumulated after 0.6.2 into one reviewable release branch. CLI/runtime and Desktop versions remain in lockstep at 0.7.0. The new runtime ownership and visible workflows require a new pre-1.0 line under the [release version rule](../../RELEASE.md#version-rule).

## Candidate scope

- Zyra owns the agent, engine, provider, terminal, protocol, client and telemetry runtime modules. Maintained TypeScript, checked-in executable output, upstream MIT attribution and compatibility aliases ship together; external Pi packages are removed from the production dependency contract. See the [runtime contract](../../src/runtime/README.md).
- Provider discovery, authentication callbacks, harness transports, worker preparation and session coordination move through the owned runtime. This includes account-aware model catalogs, child continuation, cancellation, thread messages, background service lifecycle and incremental runtime updates.
- Desktop adds chat settlement and Priority pins, clearer work and thread presentation, keyboard shortcuts, file and terminal navigation, provider/default-chat settings, and DevScope project discovery. Browser work includes background ownership, recovery pages, bookmarks and extension installation.
- Plugin connections include scoped MCP clients, application views and Google Gmail, Calendar and Drive adapters. Connected account grants and tool approval remain separate boundaries; candidate tests must prove both.
- Mobile-host, voice, terminal and startup performance work accumulated in the same checkout is included for review. This release candidate does not establish Android device acceptance or live provider parity.

## Existing data and authority

The owned runtime retains historical Pi import aliases for extensions and readers for legacy session files and manifests. Credentials remain in Zyra-owned storage; credentials from another application are not imported automatically. These are implementation contracts, not a claim that every existing installation has passed an upgrade test.

Review authentication, persistence, cancellation, tool authority and cross-surface behavior before promotion. Do not run a chat migration or change stored credentials as part of preparing this branch. Reverting source changes cannot undo data written by a running candidate; preserve user data and assess format compatibility before rollback.

## Verification and publication

Maintainer-local release-cycle context is indexed by `docs.local/README.md`; see `docs.local/runbooks/manual-publishing-workflow.md` and version handoffs under `docs.local/releases/`. These ignored files are available in the maintainer's checkout.

The pull request records commands, actual results and unresolved failures for its exact candidate commit. Required release gates remain in [RELEASE.md](../../RELEASE.md); failed checks keep this candidate in draft.

Native Windows, macOS and Linux builds, installed-app upgrade checks, updater metadata, signatures/notarization, checksums and downloaded-draft readback remain required before publication. The unsigned/security exception approved for 0.6.2 does not apply to 0.7.0. No production tag or GitHub release is created by candidate preparation.

Visual UI acceptance, protected-media playback, real provider traffic and physical Android-device checks remain separate from source contracts and isolated fixtures. Do not present passing local tests as proof of those paths.
