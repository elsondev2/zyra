# Zyra 0.7.1

Status: candidate preparation. Not published.

The maintainer selected Windows Dev preview build 24 as the source baseline and requested a patch release at 0.7.1. The baseline is `ffaf40ec03ad304d31d8dbf8ba8677181eee05e9`, built by [the successful Windows preview run](https://github.com/elsondev2/zyra/actions/runs/39267509804). CLI/runtime and Desktop versions remain in lockstep.

## Scope

Retain the selected preview's application behavior. Do not include subsequent development-checkout changes. Candidate preparation updates lockstep package/lock versions, release documentation, the version-pinned release test and manual workflow default. A type-only developer IPC import explicitly identifies the already-injected trusted facade; its transpiled runtime output is identical to the selected preview. The security and actual sender/frame/onboarding regression tests remain enforced.

The selected snapshot includes chat history and settlement recovery, agent/workflow navigation and retained searches, provider credential/network recovery, account-owned quota controls, deferred tool disclosures, developer workspace safeguards and cancellation ownership fixes. This scope identifies the selected snapshot, not a claim that each workflow has passed installed-app acceptance.

Release verification also exposed a Bun compatibility failure in callback shutdown: `socket.destroySoon()` is unavailable there. Callback cleanup now uses `socket.end(() => socket.destroy())` to retain the flush-before-close behavior on Node and Bun. The existing successful/cancelled browser-sign-in and speculative-connection regression passes under both runtimes. Account source assertions are aligned with the already-selected account ID, named imports, row display options and Desktop credential notice; no account controls or trust checks are removed.

## Distribution exception

The maintainer explicitly approved an exception for 0.7.1 only: Windows packages may be unsigned, macOS packages may be unsigned and unnotarized, and publication may retain the unresolved CastLabs browser security patch gap documented in [the release contract](../../RELEASE.md#desktop-compatibility-baseline).

Publish those limitations in the release notes. Do not generate false signing evidence, weaken the normal tagged release gates, or treat this as permission for future unsigned releases. Use the existing unsigned native rehearsal path and independently verify the complete upload set before an explicitly approved publication.

## Remaining gates

- Commit and push the final versioned candidate; obtain fresh exact-source Windows preview evidence. Build 24 used source version 0.7.0 and cannot satisfy 0.7.1 versioned-candidate approval.
- Run the required privacy, release, compatibility and native Windows/macOS/Linux gates for the final candidate.
- Keep candidate source identity consistent through integration, packaging, draft target and production tag. Do not rename preview installer bytes into stable assets.
- Verify complete updater metadata, artifact names, sizes and SHA256SUMS; download the draft assets again and validate those remote bytes.
- Record installed-upgrade, protected-media, live-provider and physical-device acceptance separately. No app installation, restart or saved-data migration is part of candidate preparation.
