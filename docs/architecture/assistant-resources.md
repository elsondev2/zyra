# Assistant Resources Architecture

Resources is a visual, read-only Inspector shelf for images and links derived from the selected chat’s persisted Review model. It does not own files, browser pages, attachments, or turn history.

## Source

`AssistantPage.tsx` already merges the persisted Review index, loaded messages and activities, lazy turn detail, and selected project root into `AssistantDiffTurn[]`. `AssistantDiffPanel.tsx` passes that same turn model to Resources.

`assistant-resource-index.ts` projects these turns into resource identities. It performs no IPC reads and keeps no second chat store.

## Included resources

Resources intentionally includes only:

- local images referenced, attached, changed, or generated by the chat;
- pasted or clipboard image attachments;
- remote image URLs, including Markdown image syntax;
- safe HTTP(S) links;
- classified package links.

Code files, text documents, pasted text, and other non-image attachments are excluded at the index boundary rather than hidden only in the UI.

## Identity and provenance

Canonical local image paths merge evidence from multiple turns. Windows drive and UNC paths compare case-insensitively; POSIX paths remain case-sensitive. Normalized URLs deduplicate exact web destinations. Clipboard images use a bounded content identity and remain local attachment data.

Every resource retains source labels, occurrence count, up to 24 newest origins, the latest originating turn, and the latest exact Review target when one exists.

## Bounds and rendering

The projection is newest-first and bounded by:

- 500 visible resource identities;
- 2,000 turns;
- 2,000,000 total prompt/response characters;
- 50,000 characters per text field;
- 80 extracted references per text field;
- 24 retained origins per resource.

Once the identity limit is full, older free-text extraction stops because it cannot add a visible card. Structured changes and image attachments still pass through the bounded identity map.

The workspace renders a fixed two-column card grid. Each virtual row contains up to two 176px cards and only viewport rows plus overscan are mounted. Search uses a deferred query. Resources remains mounted while another Inspector workspace is active, preserving search, filter, and native scroll state.

## Card previews

Image cards use an existing safe source:

- local image path → Zyra’s registered file protocol;
- clipboard image reference → existing attachment resolver;
- retained image data URL → image-only data source;
- remote image URL → Chromium image loading with no referrer.

Link cards request bounded Open Graph metadata through the desktop main process. When available they show the site image, title, description, site name, hostname, and destination path. Sites without usable metadata retain the hostname-only favicon fallback. No page scripts execute for card previews.

The metadata reader permits public HTTP(S) pages only. It rejects credentials, localhost and private/link-local/reserved IP ranges, validates every DNS answer and redirect, pins the validated address into the request, sends no cookies or referrer, uses a five-second timeout, and stops at `</head>` or 256 KB. Open Graph images must resolve publicly and use HTTPS. Main-process and renderer caches are bounded, and concurrent card requests are deduplicated.

## Existing owners

Resources routes actions instead of duplicating state:

- local image open/new preview tab → `openAssistantFileTarget` and `useFilePreview`;
- recorded image change → Review with the exact `AssistantDiffTarget`;
- originating turn → Review turn selection and lazy detail loading;
- website card metadata → guarded main-process Open Graph reader through typed preload IPC;
- HTTP(S), remote image, or package link → retained Browser through a one-shot navigation request;
- projectless web link → guarded external browser IPC;
- clipboard image → `assistant.resolveClipboardAttachment`;
- retained inline image → `AssistantAttachmentPreviewModal`;
- copy → existing clipboard preload API.

## Current scope

Browser screenshots, recordings, and future Subagent artifacts are not represented until those systems expose authoritative artifact contracts.
