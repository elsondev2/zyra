Zyra / Architecture Plan / Revision 2 / 11 July 2026

Ultra needs a model-routing agent fleet

The main orchestrator owns the goal. It may assign each bounded task to any authenticated compatible model, watch the work, escalate weak results, and return one coherent answer through Zyra.

Ship native max first. Then build Ultra as a dynamic, checkpointed orchestration runtime: strong root, task-aware model routing, quiet multi-agent surfaces, isolated writes, automatic quality escalation, and visible cost control.

02 / CURRENT STATE

The transport is close. The controller does not exist.

Zyra already owns model-specific effort state and a provider-request hook. Pi 0.80.6 now represents max natively. Pi intentionally leaves subagents to extensions.

PROTECT

04 / MODEL ROUTING

The orchestrator can choose any allowed model

Workers inherit the project, authentication boundary, permissions, and budget policy. They do not automatically inherit the root model. ModelRouter selects from the live authenticated catalog using task requirements and provider availability.

GPT-5.6 LUNA / DEFAULT CHEAP WORKER

Gather and execute

Fast, bounded tasks with a clear success condition.

  • Search and file inventory
  • Mechanical edits and migrations
  • Test, lint, extraction, summaries
  • Read-only parallel fan-out
GPT-5.6 TERRA / GENERAL WORKER

Implement and verify

Medium-hard work that needs independent engineering judgment.

  • Scoped feature implementation
  • Code review and debugging
  • Plan validation
  • Bounded worktree ownership
GPT-5.6 SOL / STRONG ROOT OR SPECIALIST

Resolve ambiguity

High-risk or difficult work where mistakes dominate token price.

  • Root orchestration and synthesis
  • Architecture and security judgment
  • Failed-worker recovery
  • Final high-risk review

Defaults are routing hints, not limits. The controller evaluates the artifact or verifier result. A miss can automatically retry or escalate Luna -> Terra -> Sol inside the configured budget. The user sees the reason, model, and incremental cost. No provider or model is impersonated.

06 / DELIVERY ROADMAP

Sequence the monster

Each phase has a hard gate. Ultra stays hidden until transport, routing, lifecycle, recovery, and both product surfaces are independently proven.

Phase 0
Baseline

Freeze evidence and behavior

  • Capture current Pi and Zyra effort behavior.
  • Add request-payload tests for low through max.
  • Record resume, compaction, and model-switch behavior.
  • Keep Ultra unavailable.
GATE: CURRENT MAX PATH REPRODUCIBLE
Phase 1
Native max

Upgrade Pi to 0.80.6

  • Upgrade coding-agent and TUI packages together.
  • Remove max -> xhigh conversion.
  • Use native Pi capability and persistence paths.
  • Retain an isolated legacy adapter only if needed.
GATE: MAX SURVIVES REQUEST, COMPACTION, RESUME
Phase 2
Capability

Separate effort, root eligibility, and worker eligibility

  • Add per-model effort and orchestration metadata.
  • Expose Ultra root mode only for Sol and Terra.
  • Allow Luna and other authenticated compatible models as workers.
  • Persist transportEffort=max and delegation=proactive.
GATE: ROOT AND WORKER CAPABILITIES RESOLVE INDEPENDENTLY
Phase 3
Controller

Build durable fleet state

  • Create controller, event protocol, snapshot store, and state machine.
  • Create stripped-down child sessions without normal chat persistence.
  • Inherit project, auth boundary, permissions, and policy; route model separately.
  • Checkpoint every node and disable silent recursive orchestration.
GATE: RESTART AND LIMIT RECOVERY RESUME ONLY INCOMPLETE NODES
Phase 4
Router

Route by task requirement and live availability

  • Build the live model catalog and task envelope.
  • Score intelligence, taste, risk, execution fit, cost, and limits.
  • Add allowlists, budget ceilings, provider policy, and routing explanations.
  • Evaluate results and escalate automatically inside policy.
GATE: ROUTING AND ESCALATION ARE DETERMINISTIC AND EXPLAINABLE
Phase 5
Workflow

Materialize a dynamic DAG

  • Expose spawn, message, follow-up, wait, list, and interrupt.
  • Let the orchestrator invent bounded roles from the problem.
  • Fan out independent reads; stack dependent writes and PRs.
  • Add heartbeat, timeouts, artifact harvest, verifier loops, and worktrees.
GATE: FAILED OR BLOCKED NODES RECOVER WITHOUT REPLAYING COMPLETED WORK
Phase 6
TUI

Ship the terminal agent panel

  • Add stable fleet summary and /agents panel.
  • Show model prefixes, state, elapsed time, scope, and usage.
  • Add inspect, message, stop, retry, escalate, and artifact actions.
  • Keep child event streams outside the root transcript.
GATE: EVERY ACTIVE WORKER IS VISIBLE, INSPECTABLE, AND STOPPABLE
Phase 7
Desktop

Ship the desktop Agent Rail

  • Subscribe to the same controller snapshot and event protocol.
  • Add tree, inspector, diffs, artifacts, errors, and usage views.
  • Persist panel state without making renderer state authoritative.
  • Notify only on blocks, required input, and completion.
GATE: TUI AND DESKTOP DISPLAY IDENTICAL FLEET TRUTH
Phase 8
Release

Activate Ultra behind explicit policy

  • Enable proactive routing only at Ultra.
  • Default to four sessions including root; make limits configurable.
  • Show API billing and subscription quota behavior clearly.
  • Require an explicit grant for merge, deploy, or irreversible actions.
GATE: CHAOS, BILLING, RESUME, AND RELEASE TESTS PASS

08 / STATE CONTRACT

Ultra must remain explicit in Zyra

Pi owns the model request and native max state. Zyra owns the additional orchestration state and exact Ultra persistence.

09 / RISK REGISTER

Failure modes to design around

R1
Parallel file conflicts

Workers declare scope. The controller blocks or warns on overlap and the root reviews all resulting diffs.

R2
Usage multiplication

Default concurrency stays at four including root. API mode displays a separate-billing warning before activation.

R3
Orphaned processes or sessions

Every child belongs to an AbortController tree. Root exit and disposal await child teardown.

R4
Transcript and memory pollution

Child sessions are ephemeral. Only concise final results and selected evidence enter root context.

R5
Weak or wasteful model routing

Capability comes before token price. Every decision records its signals; verifier failures trigger bounded escalation rather than silent acceptance.

R6
Workflow replay after limits

Every completed node and artifact is checkpointed. Resume schedules only incomplete or invalidated nodes.

R7
Interface overload

The root transcript stays quiet. The fleet appears as a summary plus an optional tree and inspector on both surfaces.

R8
Upstream Pi merge friction

Pi-facing adapters stay at the boundary. The controller uses public session and tool contracts rather than patching node_modules.

10 / ACCEPTANCE GATES

Definition of implemented

Ultra sends reasoning.effort=max on both API and subscription transports.
Sol and Terra can be Ultra roots; Luna can be selected as an Ultra worker.
Max and lower levels prohibit unsolicited child creation.
The router selects models from task signals, live authentication, allowlists, and budget.
A failed quality gate can escalate Luna to Terra or Sol without losing prior evidence.
Ultra creates task-specific roles and a dynamic DAG instead of fixed worker archetypes.
Resume restores exact Ultra state rather than only Pi's max state.
A 94-of-100 interruption resumes remaining nodes without replaying completed nodes.
Root cancellation leaves no active child sessions or subprocesses.
TUI and desktop render the same controller snapshot and never interleave child chatter in root chat.
Model, routing reason, state, scope, elapsed time, usage, and worktree are inspectable.
Overlapping write scopes produce a visible conflict signal.
Disjoint reads run in parallel; dependent writes and PRs remain ordered.
Merge, deploy, and irreversible actions require the configured explicit grant.
The full Zyra release gate passes without timing-test regressions.
Recommended first implementation move

Create a clean native-Max changeset against Pi 0.80.6. Keep Ultra hidden there. The first orchestration changeset should define controller events, durable snapshots, and the task envelope before either interface or proactive spawning is added.
